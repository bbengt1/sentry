# Requirements: Sentry AI

**Defined:** 2026-08-11  
**Milestone:** v0.3 Metric Depth Calibration UX  
**Core Value:** Reliable camera-only depth + obstacle awareness and object recognition that makers can run locally and plug into their robots — without proprietary sensors or cloud AI.

## v0.3 Requirements

Requirements for this milestone. Each maps to roadmap phases (13+).

### Calibration core

- [x] **CAL-01**: Maker can fit a global monocular depth scale from ground-truth samples (known distance preferred; known height supported when geometry is defined)
- [x] **CAL-02**: System rejects invalid fits (too few samples, residual too high, inconsistent signs) and never applies a bad scale
- [x] **CAL-03**: Active calibration transforms depth maps after the depth model runs and before PerceptionStore publish (single truth for all consumers)
- [x] **CAL-04**: When calibration is applied and valid, depth products use `depth_kind=metric_calibrated` and `unit="m"` together
- [x] **CAL-05**: Relative and uncalibrated depth never claim meters (`unit=null` / honest kind) on store, snapshot, Live Preview, and `/v1`

### Wizard UX

- [x] **WIZ-01**: Maker can run a Live Preview calibration wizard to collect samples and stage a fit before commit
- [x] **WIZ-02**: Maker can Apply or Cancel calibration; Cancel leaves no calibrated state or meter claims
- [x] **WIZ-03**: Wizard shows clear feedback (sample count, residual/status, calibrated vs relative labeling)
- [x] **WIZ-04**: Draft/staging mode never claims `metric_calibrated` on the live perception stream until Apply

### Free-space metric path

- [x] **FS-01**: Free-space products use `units="m"` only when underlying depth is `metric_calibrated`
- [x] **FS-02**: Free-space does not flip unit labels while still computing pure ordinal percentile nearness as if meters
- [x] **FS-03**: Free-space smoother/state resets on calibration apply and clear so stale ordinal/metric state does not ghost

### Persistence

- [x] **PER-01**: Maker can save calibration keyed by `camera_id` (and fingerprint fields needed for safety)
- [x] **PER-02**: On `sentry serve`, valid saved calibration can re-apply for matching camera/fingerprint without re-running the wizard
- [x] **PER-03**: Mismatched fingerprint (resolution, model/mode, camera_id) refuses auto-apply and keeps honest relative depth
- [x] **PER-04**: Maker can clear/invalidate stored calibration and return to uncalibrated relative depth

### Operator surfaces

- [x] **OPS-01**: Status/banner (and Live Preview) show whether calibration is active and base honesty (relative vs calibrated)
- [x] **OPS-02**: Operator docs describe the calibration wizard, persistence path, and honesty rules (no vehicle-grade claims)
- [x] **OPS-03**: Automated tests cover fit/apply/honesty/persist with synthetic data (no physical room required in CI)

## Future Requirements

Deferred beyond v0.3. Tracked but not in current roadmap.

### Calibration advanced

- **CAL-F01**: Full chessboard / photogrammetry intrinsic suite as primary path

## Out of Scope

| Feature | Reason |
|---------|--------|
| Vehicle-grade / FSD metric accuracy claims | Product thesis: maker monocular ≠ AV |
| LiDAR-required calibration | Camera-only stack |
| New heavy deps (SLAM, Open3D, scipy, React) | Research: zero new packages; extend existing stack |
| Changing ORT/TRT fixed-class detection factory | Closed in v0.2; not this milestone |
| Motor control / safety interlocks from depth | Perception-only API boundary |
| Language/CLIP automatic scale without user GT | Honesty and anti-feature risk |
