    - stop() ends thread, status stopped, source closed

    - Fake source that fails N times then succeeds: status returns to streaming; frames resume on bus

    - UI/API subscribers only call bus.get_latest / loop.status — never source.read

    1. Implement `CaptureLoop` in capture/loop.py:
       - Constructor takes CameraSource-compatible source, FrameBus, optional backoff params (initial_backoff=0.25, max_backoff=5.0, factor=2.0)
       - start(): set status STARTING; spawn daemon thread running _run; do not block forever on start
       - stop(): signal stop event; join thread with timeout; close source in finally; status STOPPED
       - _run loop:
         - ensure source open
         - read ImageFrame; set t_ingest on meta if still None or always stamp ingest at bus boundary (prefer: if meta.t_ingest is None, rebuild/copy with t_ingest=time.time() — ImageFrame.meta is Pydantic model so use model_copy(update={"t_ingest": ...}) when stamping)

         - status STREAMING; clear status_detail; reset backoff on success
         - on SourceDisconnected / OSError / RuntimeError from read: status RECONNECTING; set status_detail to str(exc); close source; sleep backoff; open again; multiply backoff up to max
         - on open failure: status ERROR or RECONNECTING per RESEARCH (ERROR until first success, then RECONNECTING); continue backoff
       - Expose thread-safe properties: status: SourceStatus, status_detail: str | None, source_name, camera_id (from source if available)
       - Optional snapshot method returning a plain dict or Pydantic DTO fields needed later by /api/status (status, status_detail, frame_id from bus latest, etc.) — keep internal; API wiring is 02-03
